设计理念符号系统
定义：
外延的符号：
若X是一个概念，则Ext(X)表示X的外延。
封装的定义：
若f: Ext(X)→Ext(Y)，则称概念X相对于概念Y在映射f上是封装的，即X□(→┴f封装 ) Y（可以这么理解：用f封装X，然后把用f封装后的X交给Y）。
映射系统的定义：
映射系统首先是一个系统，其中有3个要素：第一个是环境条件X这个概念；第二个是导向映射f这个映射；第三个是导致的全局状态Y这个概念。其中X□(→┴f封装 ) Y。记S=<X,f,Y>。
某映射系统实现了某效果的定义：
对于任意映射系统S和任意效果E，若S导致的全局状态的外延⊆E导致的全局状态的外延，则称S实现了E。
公理：
(1)：任何可设计系统都是一个映射系统。
(2)：越真善美的可设计系统越优秀。
(3)：对于三要素相同的两个系统S=<X,f,Y>与T=<X,f,Y>，若S的熵比T的熵更低，那S比T更真善美。（“追求导致外部假恶丑的系统其内部更无序那它能维持的时间越少而更真善美”这样之类的反驳是不成立的，因为系统其能维持的时间也算进三要素之内的话那不管怎样都是熵越低越有序越真善美了）
推理：
(1)：如果想让映射系统S实现效果E，则需要让S导致的全局状态的外延⊆E导致的全局状态的外延，而因为S的环境条件X相对于S导致的全局状态Y在S的导向映射f上是封装的，即X□(→┴f封装 ) Y，所以f: Ext(X)→Ext(Y)，而Ext(Y) ⊆E导致的全局状态G的外延Ext(G)，所以f: Ext(X)→Ext(G)，即X□(→┴f封装 ) G，或者说S.X□(→┴(S.f封装) ) E.G。
(2)：在让可设计系统S=<X,f,Y>实现效果E时，如果想让设计（比如编程）的可设计系统更优秀，则需要让设计的系统更真善美，为了善，需要让认知成本降低，不管是单人还是多人的设计，根据上述可知，应该先在脑海中构建一套真善美的实现了效果E的映射系统S’=<X’,f’,Y’>，然后尽量让S’中有的(模式)S中也有，S’中没有的(模式)S中也没有。
(3)：设E导致的全局状态为G，在让可设计系统S_总  实现效果E时，当已有可设计系统S=<X,f,S.Y>和T=<T.Y,g,G>时，有X□(→┴f封装 ) S.Y和T.Y□(→┴g封装 ) G,这时候有X□(→┴(g∘f封装) ) G⟸S.Y⊆T.Y，所以想要构造S_总=<X,g∘f,G>实现效果E的话请务必保证Ext(S.Y)⊆Ext(T.Y)，如果不成立的话请务必调整S和T使其成立。此时系统S和系统T以及由S和T组成的系统A=<X,g∘f,G>可以视为脑海中有的(模式)，则需要设计为S和T同层级，A在S和T的上层将S和T包含在内。
定理：
1：一个更优秀的实现了效果E的映射系统A，其必然满足以下必要条件：
(1)：A的环境条件X□(→┴A的导向映射f封装 ) E导致的全局状态G。
(2)：如果想让可设计系统A=<X,f,Y>实现效果E，应该先在脑海中构建一套真善美的实现了效果E的映射系统A’=<X’,f’,Y’>，然后尽量让A’中有的(模式)A中也有，A’中没有的(模式)A中也没有。
(3)：设E导致的全局状态为G，在让可设计系统A 实现效果E时，当已有可设计系统S=<X,f,S.Y>和T=<T.Y,g,G>时，有X□(→┴f封装 ) S.Y和T.Y□(→┴g封装 ) G,这时候有X□(→┴(g∘f封装) ) G⟸S.Y⊆T.Y，所以想要构造A=<X,g∘f,G>实现效果E的话请务必保证Ext(S.Y)⊆Ext(T.Y)，如果不成立的话请务必调整S和T使其成立。
(4)：当已有可设计系统S=<X,f,S.Y>和T=<T.Y,g,G>时，系统S和系统T以及由S和T组成的系统A=<X,g∘f,G>可以视为脑海中有的(模式)，则需要设计为S和T同层级，A在S和T的上层将S和T包含在内。
(5)：其是更真善美的。
推论：
推论1（多分解下的选择显式化）：
设效果 E导致的全局状态为 G，目标系统
A=⟨Xⓜ,hⓜ,G⟩
是一个实现了效果 E的合法映射系统。由映射系统定义，h 必须是单一映射，且满足
X□(→┴h封装 ) G.
设 A可由多种方式分解，每种分解 d_i∈Ext⁡(D)对应
S_i=⟨Xⓜ,f_iⓜ,S_i.Y⟩, T_i=⟨T_i.Yⓜ,g_iⓜ,G⟩,

满足
X□(→┴(f_i 封装) ) S_i.Y,T_i.Y□(→┴(g_i 封装) ) G,S_i.Y⊆T_i.Y.
若 h不将分解方式 d_i作为显式入参，而让下游系统 T_i的选择反向影响 h，则 h的实际输出依赖于 d_i，即
h(x)=g_i (f_i (x)),在取 d_i∈Ext⁡(D)的情况下.
若存在 d_i≠d_j和 x∈Ext⁡(X)使
g_i (f_i (x))≠g_j (f_j (x)),
则 h不是单一映射。
由公理(1)，此时 A不是合法映射系统，变成了不可设计系统，设计无效，无需讨论其封装与优化。
因此，为了使 A成为合法映射系统，必须将分解方式 D作为显式入参：
h:Ext⁡(X)×Ext⁡(D)→Ext⁡(G), h(xⓜ,d_i )=g_i (f_i (x)).
此时 h为单一映射，封装成立：
X□(→┴h封装 ) G.
且对每个 d_i∈Ext⁡(D)，有
Ext⁡(h(Xⓜ,d_i ))⊆Ext⁡(T_i.Y)⊆Ext⁡(G).
进一步，由公理(3)，对于三要素相同的两个系统，熵更低者更真善美。在显式入参化后，所有分解方式实现同一效果 E，三要素可视为相同，区别仅在于描述长度，即熵。常见实现方式有三种：
	方案A：函数入参。
将每种分解方式对应的上游映射写成一个独立函数，通过函数参数传入。
描述长度为 O(k)，其中 k为分解方式总数。
	方案B：策略对象入参。
将每种上游映射封装为策略对象，通过对象参数传入。
与方案A同阶，但多出类定义、接口与实例化样板，描述长度更长。
	方案C：上层硬编码映射器。
为每种分解方式单独构造完整的
A_i=⟨X,g_i∘f_i,G⟩.

描述长度为 O(k)，但每项含完整的 S_i和 T_i，实际描述长度远大于方案A。
因此三者的熵满足
C("方案A" )<C("方案B" )<C("方案C" ).

由公理(3)，方案A最真善美最优。
结论： 在多分解与封装矛盾时，应优先选择将分解方式的选择作为显式函数入参（方案A）。该结论不是独立公理，而是公理(3)与定理1(1)(2)在具体情境下的联合应用，故列为推论。
推论2（独立选择空间下的合法分解约束）
在多分解工程中，若上游与下游实现方式可独立选择，则必须通过类型校验或适配器，将选择空间限制为
Ext⁡(D)={(p_iⓜ,q_j )∣Ext⁡(S_(p_i ).Y)⊆Ext⁡(T_(q_j ).Y)}.
上层界面应选择 Ext⁡(D)中的元素，而非独立选择上游与下游。
该结论是公理(1)与推理(3)在独立选择空间情境下的联合应用，故列为推论2。

设计原则是：
1：设计必须遵循该设计理念符号系统中体现的所有设计理念。
2：设计必须遵循公理(1)(2)(3)中对更优秀的可设计系统的要求。
3：要做满足定理1中提到的必要条件的更优秀的可设计系统。
4：要做满足推论的对更优秀的系统的要求的可设计系统。
5：经验总结出来的设计原则：用实在的东西把不实在的东西转化为实在的东西。
6：经验总结出来的设计原则：对于可设计系统为代码系统的情况，所有function在不违反其它设计原则的前提下尽量都：统一无返回值，在定义点和调用点的参数列表中用“/*->*/”等可以塞进参数列表的注释分开入参和出参，左边是入参（非只写入的），右边是出参（非只读取的）（必然注入的缓冲区），然后这样参数列表就可以只需要一行代码，而且还可以有DPS（Destination-Passing Style）式编程注释（这里的话是提到的“/*->*/”）。至于python，要是没那么严格的话（比如伪代码或者不需要发布的代码）就在入参和出参中间插入一个参数，定义点是定义参数“_: "->"”，通过类型注解实现DPS式编程注释，调用点是传入参数“"->"”，通过用不到的字符串参数实现DPS式编程注释。然后如果function是面向对象的方法并且这个面向的对象是出参的话，那改为左边是出参、右边是入参，“->”改为“<-”，如果这个面向的对象不是出参的话就不要改（阅读的时候可以将“=”视为特殊的“<-”），比如一个类有一个属性y，这个类有一个方法f(x, z)：y=x+1;z=x+1，调用后这个类的实例的属性y变成x+1，传入的z变成x+1，那么这个方法f(x, z)应该写为f(z /* <- */, x)，但是如果f(x, z)：z=x+1的话，那这个方法f(x, z)应该写为f(x /* -> */, z)。另外，对于原地读取并修改的对象，其既是入参又是出参，要同时在参数列表的入参侧和出参侧都放一个参数，调用时这两个参数位都传入同一个的该参数，由于大部分编程语言不支持function定义点的参数列表写同名参数，所以采用该对象入参的参数名为原名，出参的参数名为原名加“_self”后缀（如“x_self”，允许随编程语言的风格的不同而不同，比如在驼峰命名风格的语言中可以写作“xSelf”），并且将原名和原名加“_self”后缀这两个参数视为同一个变量的约定，禁止在调用点在这两个参数位传入除了null之外（因为function可能对于某些参数可以选择读取或者不读取、写入或者不写入，这时候只用bool标志来决定是否读取或者写入就会导致实际上不读取或者不写入了但是仍然传入非null对象的实际上违背设计原则的情况，所以允许传入null来表示这时候没有这个参数位）的两个不同变量，禁止在function的算法中假设这两个参数指向除了null之外的不同对象，二者必须始终视为同一对象的两个访问位（除了传入null之外），并且function内部只读取的对这个对象的引用只使用原名（入参名）进行读取，只写入的对这个对象的引用只使用“_self”后缀出参名进行写入，既读取又写入的对这个对象的引用优先考虑使用入参名进行读写，如果条件不允许的话再使用出参名进行读写。至于其它编程语言，同理处理。对于其它类型的可设计系统也是同理。
