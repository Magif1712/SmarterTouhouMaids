符号系统
公理：
任何代码系统都是一个映射系统
定义：
外延的符号：
若X是一个概念，则Ext(X)表示X的外延。
封装的定义：
若f:概念X的外延→概念Y的外延，则称概念X相对于概念Y在映射f上是封装的，即X□(→┴f封装 ) Y。
映射系统的定义：
映射系统首先是一个系统，其中有3个要素：第一个是环境条件X这个概念；第二个是导向映射f这个映射；第三个是导致的全局状态Y这个概念。其中X□(→┴f封装 ) Y。记S=<X,f,Y>。
某映射系统实现了某效果的定义：
若某映射系统导致的全局状态的外延⊆某效果导致的全局状态的外延，则称该映射系统实现了该效果。
推论：
如果想让映射系统S实现效果E，则需要让S导致的全局状态的外延⊆E导致的全局状态的外延，而因为S的环境条件X相对于S导致的全局状态Y在S的导向映射f上是封装的，即X□(→┴f封装 ) Y，所以f: Ext(X)→Ext(Y)，而Ext(Y) ⊆E导致的全局状态G的外延Ext(G)，所以f: Ext(X)→Ext(G)，即X□(→┴f封装 ) G，或者说S.X□(→┴(S.f封装) ) E.G。
推理：
在让代码系统S=<X,f,Y>实现效果E时，如果想让编程的认知成本很低的话，不管是单人还是多人的，根据上述可知，应该先在脑海中构建一套真善美的实现了效果E的映射系统S’=<X’,f’,Y’>，然后尽量让f’中有的(模式)f中也有，f’中没有的(模式)f中也没有。
要做到真善美的话非常建议对于任意两个模式Y和X，如果X是Y的模式，那Y就应该在X的上层，并且，要做到X即便换了一种模式（状态、模态）（比如X可以切换到模式X1或者模式X2，比如上层ai系统(Y)中的神经网络nn(X)可以切换到bnn神经网络(X1)也可以切换到cnn神经网络(X2)）也可以不改Y的代码就可以正确运行，哪怕X的模式切换是不保留原模式、删除原模式而用新模式替换掉原模式的。如果已经做到了上一段的要求的话，那可以把这一段和上一段的要求重叠的部分去掉之后得到简化版：设E导致的全局状态为G，在让代码系统S_总  实现效果E时，当已有代码系统S=<X,f,S.Y>和T=<T.Y,g,G>时，有X□(→┴f封装 ) S.Y和T.Y□(→┴g封装 ) G,这时候有X□(→┴(g∘f封装) ) G⟸S.Y⊆T.Y，所以想要构造S_总=<X,g∘f,G>实现效果E的话请务必保证Ext(S.Y)⊆Ext(T.Y)，如果不成立的话请务必调整S和T使其成立。

设计原则是：
1.真善美
2.如果想让代码系统S=<X,f,Y>实现效果E，应该先在脑海中构建一套真善美的实现了效果E的映射系统S’=<X’,f’,Y’>，然后尽量让f’中有的(模式)f中也有，f’中没有的(模式)f中也没有
3. 设E导致的全局状态为G，在让代码系统S_总  实现效果E时，当已有代码系统S=<X,f,S.Y>和T=<T.Y,g,G>时，有X□(→┴f封装 ) S.Y和T.Y□(→┴g封装 ) G,这时候有X□(→┴(g∘f封装) ) G⟸S.Y⊆T.Y，所以想要构造S_总=<X,g∘f,G>实现效果E的话请务必保证Ext(S.Y)⊆Ext(T.Y)，如果不成立的话请务必调整S和T使其成立。
4.经验总结出来的设计原则：用实在的东西把不实在的东西转化为实在的东西。
5.经验总结出来的设计原则：所有function在不违反其它设计原则的前提下尽量都：统一无返回值，在定义点和调用点的参数列表中用“/*->*/”等可以塞进参数列表的注释分开入参和出参，左边是入参，右边是出参（必然注入的缓冲区），然后这样参数列表就可以只需要一行代码，而且还可以有DPS式编程注释（这里的话是提到的“/*->*/”）。至于python，要是没那么严格的话（比如伪代码或者不需要发布的代码）就在入参和出参中间插入一个参数，定义点是定义参数“_: "->"”，通过类型注解实现DPS式编程注释，调用点是传入参数“"->"”，通过用不到的字符串参数实现DPS式编程注释。然后如果function是面向对象的方法并且这个面向的对象是出参的话，那改为左边是出参、右边是入参，“->”改为“<-”，如果不是出参的话就不要改。至于其它语言，视具体情况处理。
